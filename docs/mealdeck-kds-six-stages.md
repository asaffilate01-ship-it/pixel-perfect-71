# Six-stage kitchen display — 6 November 2026

The owner requested exactly **New → Accepted → Preparing → Ready to pack → Ready for handover → Done**.

| Display stage      | Authoritative state                                                                                                                  | Staff action                                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------- |
| New                | Verified payment has released the order; `accepted_at` is null.                                                                      | Accept order.                                         |
| Accepted           | Staff acceptance is recorded; preparation remains queued.                                                                            | Start preparing.                                      |
| Preparing          | Preparation has started; at least one line is unfinished.                                                                            | Tick every item, drink and attached extra as ready.   |
| Ready to pack      | Every routed line is ready. Internal `ready_to_pack` and `packing` remain within this stage.                                         | Start packing, check named bags, then confirm packed. |
| Ready for handover | Packing is confirmed; the pass is `ready_for_handoff`. Legacy sealed passes use the same label without inventing handover authority. | Confirm the customer's four-digit collection code.    |
| Done               | Server has confirmed `fulfilled` plus `handed_off` with a completion timestamp.                                                      | Read-only.                                            |

Six touch-friendly stage filters include counts. All active orders excludes Done. Completed orders from the last 24 hours have their own bounded list (latest 100) so they cannot displace active work or trigger new-order sounds. The kitchen timer stops at confirmed handover, not at packing. Existing acceptance queues the first receipt once; opening Done cannot print again.

## Deployment

Apply `deploy/mealdeck/post-install-migrations/20261106093358_mealdeck_kds_six_stages.sql` as one complete transaction, or use `buildManagedKdsSixStagesSql` only with a runner that already owns a single atomic transaction. The filename was generated by the official Supabase CLI. It adds only the read-only `mealdeck_ops_kds_board_v2` RPC to the independent MealDeck database. No payment settings, user verification, kitchen status mutations or original board functions are replaced.

The new RPC delegates active work to the original scoped board and independently verifies retained provider-payment evidence for completed orders. It checks matching tenant, kitchen, order, source, verified payment time and actual handover. Customer, anonymous and printer-only identities do not gain KDS permissions. Refunded/held records are not asserted to be verified completed work. Existing audit/finance history is unchanged.

Deploy the matching website code. During a rolling deployment, a missing v2 RPC falls back to the original active board, while Done explicitly reports that its history is not connected. It must not claim that a missing history function means there are no completed orders.
